# pi web

[pi](https://github.com/earendil-works/pi) 코딩 에이전트를 웹 브라우저에서 쓰는 GUI입니다.
게이트웨이 서버가 세션마다 `pi --mode rpc` 프로세스를 띄우고, 브라우저와는 HTTP + SSE로 통신합니다.

- **설치 프로그램도, `npm install`도 필요 없습니다.** 폴더를 내려받아 Node.js로 실행하면 끝입니다. Node.js 기본 모듈만 쓰고, 파일을 Program Files 같은 곳에 복사하지도 않습니다. 폴더는 어디에 둬도 됩니다.
- pi의 세션 파일(`~/.pi/agent/sessions`)을 그대로 씁니다. 터미널 pi에서 만든 세션을 웹에서 이어 갈 수 있고, 그 반대도 됩니다.
- 기본으로 이 PC(`127.0.0.1`)에서만 열립니다. 스마트폰 등 다른 기기에서 쓰려면 아래 [원격 접속](#원격-접속-집-밖의-스마트폰다른-pc에서)을 보세요.
- Windows에서 만들고 확인했습니다. macOS·Linux에서도 `node server.mjs`는 동작하도록 만들었지만 아직 확인하지 못했습니다. `piweb`·`start.cmd` 등 Windows용 도구는 Windows 전용입니다.

## 빠른 시작 (처음 쓰는 분)

1. **Node.js 22.19 이상**을 설치합니다 → <https://nodejs.org> (LTS 말고 22 이상 버전인지 확인: 터미널에서 `node -v`)
2. **pi**를 설치하고 로그인합니다 → <https://github.com/earendil-works/pi> 의 안내를 따르세요. 터미널에서 `pi`를 한 번 실행해 `/login`으로 구독이나 API 키를 연결해 두면 됩니다.
3. 이 저장소를 내려받습니다. 둘 중 편한 쪽:
   - GitHub 페이지의 초록색 **Code → Download ZIP**을 받아 원하는 곳(바탕화면 등)에 압축을 풉니다.
   - 또는 `git clone https://github.com/guineapig987/pi-web-gui.git`
4. 폴더 안에서 실행합니다.
   - Windows: **`start.cmd`를 더블클릭**
   - 그 밖: 터미널에서 `node server.mjs --open`
5. 브라우저에 <http://127.0.0.1:8787>이 열립니다. 끝낼 때는 실행 창을 닫으면 됩니다.

문제가 생기면: `node -v`가 22.19 미만이거나 pi를 못 찾는 경우가 가장 흔합니다. pi 위치를 못 찾으면 아래 `PI_CLI` 환경 변수를 지정하세요.

## 실행 옵션

| 옵션 | 설명 |
|---|---|
| `--port 8787` | 포트 (환경 변수 `PI_WEB_PORT`) |
| `--cwd <폴더>` | 처음 열 프로젝트 폴더. 생략하면 기본 작업 폴더(`Documents\pi`) |
| `--host <주소>` | 바인딩 주소 (기본 `127.0.0.1`, 환경 변수 `PI_WEB_HOST`). |
| `--open` | 시작하면서 브라우저 열기 |

| 환경 변수 | 설명 |
|---|---|
| `PI_CLI` | pi를 자동으로 못 찾을 때 `cli.js` 또는 실행 파일 경로 지정 |
| `PI_WEB_DEFAULT_DIR` | 새 세션의 기본 작업 폴더 (기본값: `~/Documents/pi`, Windows에서는 `C:\Users\<이름>\Documents\pi`. 없으면 서버가 만듭니다) |
| `PI_WEB_PI_PACKAGE` | pi 패키지 폴더 (`@earendil-works/pi-coding-agent`). 로그인 기능이 pi 라이브러리를 못 찾을 때 지정 |
| `PI_WEB_PI_ARGS` | pi에 추가로 넘길 인자. 예: `--approve` (프로젝트 `.pi/` 리소스 신뢰) |
| `PI_WEB_ALLOWED_HOSTS` | 허용할 Host 헤더 목록(쉼표 구분). 도메인이나 프록시로 접속할 때 지정 |
| `PI_WEB_MAX_UPLOAD_MB` | 첨부 파일 한 개의 최대 크기(MB, 기본 100) |
| `PI_WEB_NO_UPDATE_CHECK` | `1`이면 pi.dev에서 최신 버전을 확인하지 않습니다 (`PI_OFFLINE`도 같은 효과) |
| `PI_WEB_NO_GLOBAL_PI` | `1`이면 전역 npm 폴더에서 pi 라이브러리를 찾지 않습니다(테스트용) |
| `PI_WEB_IDLE_MINUTES` | 아무도 보지 않는 대기 세션을 종료하기까지의 시간 (기본 30분) |

pi 경로 지정 예시 (PowerShell):

```powershell
$env:PI_CLI = "$env:APPDATA\npm\node_modules\@earendil-works\pi-coding-agent\dist\bundle\cli.js"
node server.mjs --open
```

## 화면 구성 (opencode v2 스타일)

- **왼쪽 사이드바**(Claude·Codex 앱처럼): 모든 프로젝트가 폴더별로 나열되고, 각 프로젝트 아래에 실행 중인 세션(상태 점·스피너)과 저장된 세션(최근 5개, "더 보기")이 보입니다. 저장된 세션을 누르면 이어서 열립니다. 프로젝트 줄에 마우스를 올리면 그 폴더에서 **새 세션**(+)을 시작하거나 목록에서 숨길 수 있고(폴더와 기록은 그대로), 위쪽 "폴더 추가"로 프로젝트를 더하고 검색창으로 전체 세션을 찾습니다. 실행 중인 세션의 ✕는 세션 종료입니다. `π` 버튼은 홈, 사이드바는 왼쪽 위 버튼 또는 `Ctrl+B`로 접고 펼 수 있고, 좁은 화면(스마트폰)에서는 화면 위로 밀려 나옵니다.
- **홈**: 왼쪽 프로젝트 목록, 오른쪽 세션 목록(오늘/이번 주/이번 달로 묶음, 검색), 폴더 열기·새 세션.
- **새 세션 화면**: 폴더 경로, git 브랜치, 마지막 세션 시각과 하단 입력창. 시작할 때 작업 폴더는 기본적으로 `Documents\pi`입니다(`--cwd`를 주면 그 폴더). `프로젝트 생성` 버튼을 누르면 **Windows 폴더 선택 창**(주소창·탐색 창·`새 폴더` 버튼이 있는 탐색기 방식, 브라우저 앞에 뜸)이 열리고, 폴더를 만들거나 고르면 바로 그 안에서 세션이 시작됩니다(선택 창은 서버가 실행 중인 PC에 뜨므로 로컬 접속에서만 동작하고, 안 되면 앱 안의 폴더 목록으로 대신합니다). `기본 폴더로`로 되돌릴 수 있습니다. 폴더 선택창(홈의 `폴더 열기` 포함)에서도 `새 폴더 만들기`를 쓸 수 있습니다.
- **대화(턴 단위)**: 오른쪽 회색 말풍선이 내 메시지, 그 아래 에이전트 작업.
  - 생각·파일 읽기·검색·목록은 `탐색함 · 파일 2개 읽음 · 검색 1회` 한 줄로 접히고, 눌러서 펼칩니다.
  - Shell·Edit·Write는 한 줄 행으로 표시되고 출력과 diff가 바로 아래 펼쳐집니다.
  - 턴 끝에 `변경된 파일 N개` 목록, 마우스를 올리면 모델·소요 시간·토큰·비용.
  - 작업 중에는 `탐색 중 / 수정 중 / 명령 실행 중 / 응답 작성 중`과 경과 시간이 표시됩니다.
- **변경 사항 패널**(오른쪽): 세션에서 바뀐 파일 전체 diff. 폭 조절 가능.
- **입력창**: 하단 모델·생각 수준 선택, 이미지 첨부, 전송/중지 버튼. 확장의 확인·선택·입력 요청은 입력창 바로 위에 카드로 붙습니다(숫자 키로 선택).
- **명령 팔레트**: `Ctrl+K`로 명령과 모든 프로젝트의 세션을 검색합니다.

| 단축키 | 동작 |
|---|---|
| `Ctrl+K` | 명령 팔레트 |
| `Ctrl+Shift+S` | 새 세션 |
| `Ctrl+L` | 입력창으로 이동 |
| `Ctrl+Shift+E` | 변경 사항 패널 |
| `Alt+0` / `Alt+1…9` | 홈 / 세션 전환 |
| `Ctrl+B` | 사이드바 접기/펼치기 |
| `Enter` / `Shift+Enter` | 보내기 / 줄바꿈 |
| 작업 중 `Enter` / `Ctrl+Enter` | 지금 끼어들기(조향) / 끝난 뒤 보내기 |
| `Esc` | 작업 중지 (대기 메시지는 입력창으로 복귀) |
| `↑` | 이전 입력 |

그 밖에 `/` 명령 자동완성(pi 확장·프롬프트·스킬 포함), `@` 파일 경로 자동완성, `!명령`·`!!명령` 셸 실행, 이미지 붙여넣기, 세션 이름 변경·분기·복제·압축·HTML 내보내기, 다크 모드, 작업 완료 데스크톱 알림을 지원합니다.

## 파일 첨부

- 입력창의 클립 버튼, 끌어다 놓기, 붙여넣기로 **이미지 외 파일**(문서, 코드, 압축 파일 등)도 첨부할 수 있습니다. 이미지는 그대로 모델에 전달되고, 그 밖의 파일은 서버가 이 PC의 `~/.pi/agent/web-uploads/` 아래에 저장한 뒤 **경로를 프롬프트에 적어** pi가 read·bash 도구로 열게 합니다. (20MB를 넘는 이미지도 파일로 처리됩니다)
- 대화창에는 파일 이름과 크기만 칩으로 표시됩니다. 업로드가 끝나기 전에는 보낼 수 없습니다.
- 한 파일의 최대 크기는 100MB입니다(`PI_WEB_MAX_UPLOAD_MB`로 변경). 업로드한 파일은 자동으로 지워지지 않으니 필요 없으면 `web-uploads` 폴더를 직접 정리하세요.
- pi가 읽을 수 있는 형식(텍스트·코드 등)이 가장 잘 동작합니다. PDF·Office 파일 등은 모델이 쓸 수 있는 도구에 따라 읽지 못할 수 있습니다.

## 로그인과 설정

- **계정 · 로그인** (상단 사람 아이콘, 세션 메뉴, `Ctrl+K`, `/login`): 공급자를 골라 **구독 계정(OAuth)** 으로 로그인하거나 **API 키**를 저장합니다. 터미널 pi의 `/login`과 같은 pi 코드를 서버가 실행하고, 로그인 페이지 링크·기기 코드·붙여넣기 입력이 창 안에 단계별로 나타납니다. `로그아웃`은 pi가 저장한 로그인만 지웁니다(환경 변수·models.json 설정은 그대로).
  - 로그인·로그아웃이 끝나면 대기 중인 세션은 자동으로 다시 시작해 새 로그인을 적용합니다(작업 중인 세션은 끝난 뒤 `pi 프로세스 재시작`).
  - pi 라이브러리를 찾지 못하면 API 키 저장만 가능한 간단 모드로 동작하고, 구독 로그인은 터미널 pi의 `/login`을 쓰라고 안내합니다.
  - 키와 토큰은 브라우저 → 서버로만 전달되며, 화면·로그·상태 응답에 다시 나오지 않습니다. 저장 위치는 pi와 같은 `auth.json`입니다.
- **설정** (상단 톱니 아이콘, 세션 메뉴, `Ctrl+K`, `/settings`): pi의 전역 `settings.json` 중 자주 쓰는 항목(기본 생각 수준, 끼어들기·후속 메시지 전달 방식, 자동 압축, 자동 재시도, 기본 도구, 이미지, 프록시 등)을 바꿉니다. 목록에 없는 항목과 프로젝트의 `.pi/settings.json`은 건드리지 않습니다. 끼어들기·후속 전달 방식, 자동 압축, 자동 재시도는 열려 있는 세션에도 바로 적용되고, 나머지는 새 세션부터 적용됩니다. 각 항목 옆 `기본값`으로 되돌릴 수 있습니다.

## pi 업데이트

- 시작할 때와 6시간마다 설치된 pi(`pi --version`)와 최신 버전(pi.dev)을 비교합니다. 새 버전이 있으면 상단에 **pi 업데이트** 버튼이 나타나고 알림이 한 번 뜹니다.
- 현재 버전은 상단(`pi 1.1.0`)과 홈 화면 아래에 항상 표시됩니다. 눌러서 열리는 창에서 현재·최신 버전과 **업데이트 사항**(새 버전들의 변경 내역, 최신이면 현재 버전의 변경 내역)을 볼 수 있습니다. 변경 내역은 pi의 GitHub CHANGELOG에서 가져오고, 못 가져오면 설치된 pi 패키지의 CHANGELOG.md를 씁니다.
- 버튼, `Ctrl+K` → "pi 업데이트", 또는 `/update`로 대화창을 열어 **지금 업데이트**를 누르면 서버가 `pi update`를 실행하고 진행 로그를 보여 줍니다.
- 작업 중이거나 응답을 기다리는 세션이 있으면 시작하지 않습니다. 끝나면 대기 중인 세션은 자동으로 다시 시작해 새 버전을 적용합니다. 열려 있는 세션 때문에 파일이 사용 중이라 실패하면 세션을 닫고 다시 시도하세요.
- pi를 npm이 아닌 다른 방법(Nix 등)으로 설치했다면 `pi update`가 실패할 수 있습니다. 그 방법으로 업데이트하세요.

## 원격 접속 (집 밖의 스마트폰·다른 PC에서)

pi는 이 PC의 파일을 읽고 쓰고 명령을 실행할 수 있으므로, **로그인이 없는 서버를 인터넷에 그냥 열면 안 됩니다.** 그래서 공유기 포트를 여는 대신 **Tailscale**(무료 개인용 VPN, 내 기기끼리만 연결)을 쓰는 방식입니다.

### 한 번만 설정
1. 이 PC에서 Tailscale에 로그인합니다 (`tailscale up` 또는 트레이 아이콘 → Log in).
2. 스마트폰/다른 PC에도 Tailscale 앱을 설치하고 **같은 계정**으로 로그인합니다.

### 실행과 접속
```bash
npm run start:remote
```
시작할 때 화면에 "Tailscale: http://100.x.y.z:8787" 같은 주소가 나옵니다. 다른 기기의 브라우저에서 그 주소를 엽니다. Windows 방화벽 창이 뜨면 "개인 네트워크"에서 허용하세요.

HTTPS 주소(`https://pc이름.tailnet이름.ts.net`)를 쓰려면 이 PC에서 `tailscale serve --bg 8787`을 실행하세요.

### 항상 켜 두기 (창 없이, 로그온할 때 자동 시작)
Windows 전용입니다. 프로젝트 폴더 안에서 `piweb`(PowerShell에서는 `.\piweb`)을 입력하면 명령 목록과 현재 상태가 나옵니다. 처음 한 번 `piweb setup`을 실행하고 창을 새로 열면 **어느 폴더에서든** `piweb`만 입력해 쓸 수 있습니다(`piweb unsetup`으로 해제). 스크립트 실행 정책에 막히지 않도록 `piweb.cmd`가 대신 호출합니다.
```
piweb status      실행 여부와 접속 주소
piweb open        브라우저로 열기
piweb restart     코드를 고친 뒤 다시 시작
piweb log         최근 로그
piweb stop        중지        (piweb start: 시작)
piweb install     자동 시작 등록 + 시작
piweb uninstall   자동 시작 해제 + 중지
```
작업 스케줄러에 `pi-web` 항목이 만들어지고(`piweb uninstall`로 삭제), 로그는 `logs/` 폴더에 남습니다. 프로젝트 폴더를 다른 곳으로 옮겼다면 `piweb install`을 다시 실행하세요.

### 주의
- 로그인이 없으므로, Tailscale에 로그인된 내 기기는 모두 이 서버를 쓸 수 있습니다. Tailscale 계정 보안(2단계 인증)을 지키세요.
- `--remote`나 `--host 0.0.0.0`을 같은 와이파이나 공용 네트워크에서 켜면 같은 네트워크의 누구나 접속할 수 있습니다. 공용 와이파이에서는 쓰지 마세요.
- 원격 모드에서는 PC 화면에 뜨는 폴더 선택 창과 로그인용 터미널 창이 막힙니다. 폴더는 화면의 목록에서 고르세요.
- 이 PC가 꺼지거나 절전 상태가 되면 접속할 수 없습니다.

## 알려진 제한

- pi의 터미널 전용 UI(`ctx.ui.custom()` 등)와 `/settings`, `/tree` 같은 TUI 내장 명령은 RPC 모드에서 동작하지 않습니다.
- 같은 세션을 터미널 pi와 웹에서 **동시에** 열면 세션 파일이 꼬일 수 있습니다. 한쪽을 닫고 여세요.
- 프로젝트의 `.pi/` 확장·설정은 저장된 신뢰 결정이 있을 때만 로드됩니다(터미널 pi에서 `/trust`로 저장하거나 `PI_WEB_PI_ARGS=--approve`).

## 테스트

기본은 **진짜 pi**로 확인합니다. 가짜 pi(`test/fake-pi.mjs`)는 모델 호출 없이 정해진 화면·이벤트를 재현해야 하는 자동 테스트에만 씁니다.

```bash
node test/unit.mjs          # 순수 로직 (리듀서, 마크다운, 버전·첨부 처리)
node test/server-auth.mjs   # 서버 API: 로그인·설정·업데이트·업로드 (가짜 pi)
node test/real-pi.mjs       # 진짜 pi 점검 — 무료: pi 찾기·버전·로그인 상태·세션 시작·모델 목록·업로드
node test/real-pi.mjs --prompt   # + 모델에 아주 짧은 질문 2개 (로그인한 계정의 토큰을 조금 씁니다)
node test/real-server.mjs   # 진짜 pi로 화면을 직접 써 보기 (http://127.0.0.1:8791)
node test/e2e.mjs           # 브라우저 자동 테스트 (가짜 pi, Playwright 필요: npm i -g playwright)
```

- 진짜 pi 테스트는 **내 로그인(`~/.pi/agent`)을 쓰되**, 대화 기록은 임시 폴더에 따로 만들고 끝나면 지웁니다. 내 프로젝트나 기존 세션은 건드리지 않습니다.
- 계정 문제(요금제 한도, 로그인 만료 등)로 모델을 부를 수 없으면 실패가 아니라 **건너뜀**으로 표시하고 이유를 보여 줍니다.
- `npm run test:real`, `npm run test:real:prompt`, `npm run start:real`로도 실행할 수 있습니다. `npm test`는 가짜 pi 기반 테스트만 돌립니다.
